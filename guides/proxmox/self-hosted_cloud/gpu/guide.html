GPU as a Service — RTX 3060 Ti

One driver install on the Proxmox host; nvidia-container-toolkit injects the GPU into both the Jellyfin LXC and the Immich (Docker) LXC · Route B · References gathered 2026-10-05

Chosen route nvidia-container-toolkit

The model: the host installs the NVIDIA driver once and owns the kernel modules. The toolkit injects the user-space driver libraries and /dev/nvidia* device nodes into containers on demand. No driver-version matching between host and each container, no driver reinstall inside LXCs on host upgrades.

End-to-end walkthrough (host driver + toolkit + Docker runtime configuration, written for Docker-in-LXC): digitalspaceport.com — Proxmox LXC Docker GPU passthrough setup guide

Wiring the toolkit into an LXC (not just Docker)

The toolkit's LXC hook mounts the driver + binaries into the container at start. Key lines for /etc/pve/lxc/<vmid>.conf plus the PVE 9-specific fixes and debugging: forum.proxmox.com — PVE 9 nvidia-container-toolkit thread

Typical shape (verify against the thread):

  • lxc.hook.mount: /usr/share/lxc/hooks/nvidia
  • lxc.environment: NVIDIA_VISIBLE_DEVICES=all
  • lxc.environment: NVIDIA_DRIVER_CAPABILITIES=all (Jellyfin needs video; Immich ML needs compute)
  • Pre-start hook running nvidia-modprobe so the device nodes exist before the container mounts them

For Docker inside the Immich LXC: nvidia-ctk runtime configure --runtime=docker on the container side, then runtime: nvidia on services that need the GPU.

Alternative route (documented for reference)

Device-node passthrough: pass /dev/nvidia0, nvidiactl, nvidia-uvm, and caps nodes into the LXC and install a matching user-space driver inside it. More commonly documented, but every host driver upgrade must be mirrored inside each container. Forum tutorial: Jellyfin LXC with Nvidia GPU transcoding. Chose the toolkit route instead because it serves both services from one driver install.

Gotchas and notes

PVE 9.x persistence quirk Known failure mode (flagged in the project risk doc): after a host reboot, containers can fail to see the GPU until device nodes are re-created. The nvidia-modprobe pre-start hook in the forum thread is the fix. Test a full reboot after wiring this up — the accept-criteria is a clean nvidia-smi inside both LXCs post-reboot.
Verify driver visibility, not just devices A container can see /dev/nvidia* nodes and still fail if the user-space library version doesn't match the host kernel module version. With the toolkit route the hook handles matching; the failure symptom to recognize is nvidia-smi erroring inside the container while working on the host.
NVENC session cap ~3–5 concurrent NVENC sessions at the driver level. keylase/nvidia-patch lifts it if family-scale transcoding ever saturates.
Unprivileged containers only Never combine this with a privileged LXC. Privileged + GPU passthrough gives container root effective host access.
One GPU, two consumers Jellyfin transcodes and Immich ML share the card. That's fine (driver multiplexes), but a heavy ML re-scan while someone streams 4K can cause transcode stutter. Consider scheduling Immich ML scans off-peak if both ever collide.
